## Project Description (Input)
**誰が困っているか**：Markdown を扱うソフト（とその開発者）は、原文の位置を保ったまま構文の構造を知りたい。

**現状**：既存の実装（cmark など）は原文を複製したノードを作るため、元の位置と行末記号が失われやすく、原文の置き換えのような用途に使いにくい。本プロジェクトにはまだ構文木がなく、project-foundation のアリーナと確保関数を使う前提である。

**何を変えるか**：ブロックとインラインの構文木のデータモデルを用意する。
- CommonMark の全要素を表せ、方言が定める種類も登録した ID で表せる。
- ノードは原文の範囲（バイトのオフセット）と行番号だけを持ち、原文を複製しない。
- 種類ごとの属性を持つ（見出しのレベルと ATX/Setext の別、リストの種類・記号・開始番号・タイト/ルーズ、コードブロックのフェンスの文字と長さ・info の範囲、リンクと画像の参照の別・dest と title の範囲・参照先の定義、そのほか CommonMark が必要とするもの）。
- 木の構造の不変条件（範囲は内容の中にある、子は親の内側にある、兄弟は重ならず原文の順に並ぶ）を定義し、検査する関数を持つ。
- 読み取り専用でたどる公開 API（親・最初の子・次の兄弟、種類、範囲、行、属性）があり、再帰を使わずに走査できる。文書を解放する API がある。
- 公開する型として、解析の設定（方言、範囲 `[start, end)`、確保関数、ファイル名、不正な UTF-8 の扱い、資源の上限）、エラーの種類（入力の制約違反、設定の誤り、資源の上限の超過、メモリ不足）、診断（位置、重大度、メッセージ、ファイル名）と、設定を検査する関数を持つ。
- 内部専用の木を作る API を持つ。

**方針と制約**：ノードはアリーナ上の平坦な配列に置き、32 ビットの添字で親・最初の子・次の兄弟をつなぐ。公開 API は不透明なハンドルと関数で構成し、構造体のレイアウトは公開しない。再帰を使わず、状態を持たず（別々の文書を並行して使える）、公開 API は C99 で MSVC からも使えること。

**範囲外**：解析の規則（block-parser、inline-parser）、範囲から文字列を作ること（source-text）、方言の規則を登録する API（dialect-extension）、木を書き換える API、HTML などへの出力。

詳細は `brief.md` を参照。
