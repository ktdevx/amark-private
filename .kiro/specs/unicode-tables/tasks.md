- [x] 1. 入力データと生成スクリプト
- [x] 1.1 入力データを置き、その出所を記録し、行末の変換を止める
  - Unicode 18.0.0 の General Category の派生ファイルと case folding のファイルを `www.unicode.org` から、WHATWG の実体名の JSON を `html.spec.whatwg.org` から取得し、取得したままの内容で入力データの場所に置く。UCD の 2 ファイルは同じ版にする。どちらかのホストに接続できないときは、ファイルを手で作らずに作業を止め、ファイルの提供を求める
  - 入力データの説明の文書に、ファイルごとの取得元、版（実体名の JSON は取得した日）、SHA-256、利用の条件を書く
  - 入力データの行末を変換しない設定と、2 つの生成物を常に LF でチェックアウトする設定を、リポジトリの属性のファイルに書く
  - 完了の状態：3 つの入力ファイルがコミットされ、それぞれの SHA-256 が説明の文書の値と一致する。`git check-attr` で、入力データが `-text`、生成物の 2 つのパスが `eol=lf` と表示される

- [x] 1.2 生成スクリプトの引数の処理と、入力の読み取りと検査を作る
  - 標準ライブラリだけを使う Python 3.9 以上のスクリプトとして作り、型ヒントを付ける。ネットワークには接続しない。モジュールとして取り込めるようにし、読み取りの処理を関数として呼べるようにする
  - 入力と出力の場所を引数（`--data-dir`、`--output-dir`）で変えられるようにし、既定の場所はスクリプトの置き場所から決める。引数の誤りは終了コード 2 にする
  - 入力をバイト列で読む。UCD の 2 ファイルの 1 行目から版を読み、食い違えば両方の版を示して失敗する
  - 設計の Batch Contract に挙げた入力の不備（ファイルがない、行の形の誤り、未知の分類や状態、C と F の対応先の数の誤り、同じコードポイントに C と F の両方、対応先に U+0000 がある、実体名の形の誤り、`codepoints` の数やスカラー値の誤り、`codepoints` と `characters` の食い違い、表の形の上限の超過）を、ファイルと行を示して終了コード 1 で知らせる
  - 句読点（P と S）と Zs の範囲は、隣り合うものと重なるものをつなぐ。case folding は状態 C と F だけを残し、S と T を捨てる。実体名は `;` で終わるものだけを残し、`&` と `;` を除いてコードポイントを UTF-8 にする
  - 完了の状態：Python の 1 行のコマンドでスクリプトを取り込み、実際の入力データに読み取りの関数を呼ぶと、句読点 359 範囲、Zs 7 範囲、状態 C 1,501 項目、状態 F 105 項目、実体名 2,125 個が得られる。UCD の 1 ファイルの 1 行目の版を書き換えた一時的な複製を `--data-dir` で読ませると、2 つの版を示して終了コード 1 で終わる
  - _Requirements: 1.3, 1.6, 1.7, 2.5, 6.4_

- [x] 1.3 生成物の書き出しと、最新であることの検査（`--check`）を作り、生成物をコミットする
  - 2 つの生成物（Unicode の表、実体名の表）を、設計の表の形と先頭の形式のとおりに、ASCII と LF だけでメモリ上に組み立てる。日時、ホスト、絶対パス、Python の版を書かない
  - 先頭の 5 行以内に著作権表示と SPDX（Unicode の表は `MIT AND Unicode-3.0`、実体名の表は `MIT AND BSD-3-Clause`）を置き、生成物である旨、入力の名前と版（実体名の JSON は SHA-256）、スクリプトの名前、データの出所とライセンスの名前、取り込む `.c` の名前を書く
  - 表にポインタを入れず、項目の数をマクロで持たせる。実体名の文字の配列は、文字列リテラルではなく、波括弧で囲んだ文字の初期化子で書き、終端の NUL を持たせない（隣り合う文字列リテラルがつながると C99 の最低限 4,095 文字を超え、`-Wpedantic` と `-Werror` でビルドが失敗するため）
  - すべてを組み立て終えてから、一時ファイルに書いて置き換える。`--check` ではファイルを書かず、違うファイルの名前、差分の先頭、直し方を示して終了コード 1 で終わる
  - 完了の状態：生成を 2 回続けて実行しても生成物のバイト列が変わらず、`--check` が終了コード 0 で終わる。2 つの生成物をコミットした状態で、既存の `checks.license_headers` が通る。C としてのコンパイル（GCC と Clang の両方で、警告のエラー化を有効にして）は 2.1 と 2.2 で確かめる
  - _Requirements: 1.1, 1.2, 1.4, 1.5, 1.6, 2.1, 2.4, 3.3, 3.4, 8.4, 9.3_

- [x] 1.4 生成スクリプトの自己テストを作る
  - 一時ディレクトリに小さな入力を作り、入力と出力の場所を指定してスクリプトを実行する。リポジトリのファイルには書かない
  - 再現性：同じ入力で 2 回生成した結果がバイト単位で同じで、CR がなく ASCII だけである
  - 入力の不備：ファイルがない、行の形の誤り、UCD の版の食い違い、F の対応先が 4 つ、の各場合に、終了コード 1、標準エラーにファイルの名前（分かれば行も）があり、先に置いた生成物が変わらない
  - `--check`：生成の直後は終了コード 0、生成物を 1 バイト変えると終了コード 1 でそのファイルの名前を示す。どちらでも生成物の内容と更新の時刻が変わらない
  - 内容の規則：先頭 5 行に著作権表示と SPDX があり、生成物である旨、入力の名前と版、スクリプトの名前、出所とライセンスの名前がある。状態 S と T の対応と、`;` のない実体名が出力にない
  - 自己テストで生成スクリプトの誤りが見つかったら、スクリプトを直し、生成物を再生成してコミットし、`--check` が通ることを確かめる
  - 完了の状態：自己テストのスクリプトを実行すると、すべてのケースが通って終了コード 0 で終わる
  - _Requirements: 1.2, 1.4, 1.5, 1.6, 1.7, 2.5, 3.2, 3.4, 6.4, 9.3_

- [ ] 3.1 判定と case folding の単体テストを作る
  - テストのターゲットに入力データの場所をコンパイルの定義として渡し、内部の関数のテストとして登録する
