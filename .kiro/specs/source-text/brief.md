# Brief: source-text

## Problem
ノードは原文の範囲しか持たない。そのため利用者は、範囲の中にあるコンテナのプレフィックス（`> ` やリストの字下げ）、タブの一部だけが消費された残り、エスケープ、文字参照を、自分で処理しなければならない。これは仕様の細部を知らないと正しく書けない。

## Current State
block-parser が行ごとのプレフィックスの情報を記録してから着手する。

## Desired Outcome
- ノードの範囲から、論理的な文字列を組み立てる API がある。
  - コンテナのプレフィックスを除く。
  - タブの残りの桁を空白で補う。
  - 行の境目を `\n` にする。
  - コードブロックやコードスパンなど、種類ごとの決まり（コードスパンの前後の空白 1 つの除去など）に従う。
- 意味上の値を得る API がある。エスケープと文字参照を文字に戻した、リンクの dest と title、コードブロックの info 文字列、テキストの内容。
- 結果は、呼び出す側が渡すバッファか、確保関数で作る文字列で返す。どちらも原文は変更しない。
- 範囲そのもの（原文のバイト列）を、そのまま取り出せる。原文を完全に復元するために使う。

## Approach
block-parser が記録した行ごとの「内容が始まる位置と、補う空白の数」を使い、行を順につなぐ。エスケープと文字参照は unicode-tables の実体名の表を使って戻す。処理は 1 回の走査で行う。

## Scope
- **In**:
  - 論理的な文字列を組み立てること
  - エスケープと文字参照を文字に戻すこと
  - dest・title・info・テキストの意味上の値
  - 原文の範囲をそのまま取り出すこと
  - 単体テスト
- **Out**:
  - URL のパーセントエンコードや HTML のエスケープなど、出力の形式に固有の処理（出力する側の責任）
  - 原文の置き換え、翻訳の単位への分割（利用者側）

## Boundary Candidates
- 論理的な文字列を組み立てること（プレフィックス、タブ、改行）
- 意味上の値を得ること（エスケープ、文字参照）

## Out of Boundary
- 木を書き換えること、Markdown を書き直すこと

## Upstream / Downstream
- **Upstream**: block-parser（行ごとのプレフィックスの記録）、syntax-tree、unicode-tables
- **Downstream**: spec-conformance（テスト用の HTML 出力）、利用者

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: inline-parser（同じ範囲を解析する。並行して進められる）

## Constraints
- 入力を変更しない。
- 状態を持たない。結果を書き出すバッファは、呼び出す側が渡すか、確保関数で作る。
