# Product Overview

amark は、Markdown の構文を木として表し、原文に忠実に解析する C99 のライブラリである。Markdown を扱うソフト（エディタ、変換ツール、翻訳支援、検査ツールなど）の開発者が、CommonMark に完全に準拠した解析結果を、原文の範囲（オフセットと行番号）として受け取れる。

## Core Capabilities

- **構文木**：ブロックとインラインの木。CommonMark の全要素と、方言が定める種類を表す。ノードは原文の範囲と行番号だけを持ち、原文を複製しない。木は読み取り専用でたどる。
- **解析**：CommonMark 0.31.2 に準拠したブロックの解析とインラインの解析。
- **原文の文字列の取り出し**：ノードの範囲から論理的な文字列を組み立てる。エスケープと文字参照を文字に戻し、dest・title・info の意味上の値を返す。
- **拡張点**：方言（GFM など）を、本体を変えずに差し込める。方言の規則が返した結果は本体が検査し、不正なら診断を出して木を壊さない。

## Target Use Cases

- 原文の位置を保ったまま、Markdown の構造を調べる（検査、索引、ハイライト）。
- 原文の一部だけを置き換える（翻訳、自動修正）。変えない部分は書式も行末記号もそのまま残す。
- 信頼できない入力を安全に解析する（資源の上限を設定できる）。
- 独自の出力（HTML など）を、木と文字列の取り出しの上に利用者が作る。

## Value Proposition

どの設定でも、次の性質を保証する。新しい機能や変更は、これらを損なってはならない。

- **どの入力も文書になる**：CommonMark に構文エラーはない。失敗するのは、入力の制約違反（設定によって UTF-8）、設定の誤り、資源の上限の超過、メモリ不足だけである。
- **仕様に準拠する**：CommonMark の spec.txt をすべて通る。規則を設定で変えることはしない（タブ幅 4、ラベルの上限 999 文字など）。
- **原文を失わない**：入力を変更せず、範囲から原文を完全に復元できる。行末記号も入力のまま保つ。
- **病的な入力に強い**：時間は入力の長さにほぼ比例し、再帰を使わない。
- **状態を持たない**：グローバルな状態も I/O もない。同じ入力と設定からは同じ木ができ、別々の文書は並行して解析できる。
- **失敗が局所的**：失敗したときは確保したものをすべて解放し、部分的な木を返さない。

## Product Boundary

ライブラリが責任を持つのは、メモリ上のバイト列の解析と、その結果の読み出しまでである。次のものは含めない。

- **利用者に任せるもの**：I/O、BOM の除去、フロントマターなど本文の外側の解析（解析する範囲 `[start, end)` の指定で除く）、用途に固有の処理（翻訳の単位への分割など）。
- **公開しないもの**：HTML 出力（テスト専用のものだけを持つ）。
- **後の段階の候補**：木から Markdown を書き出す処理、原文を差し替える補助 API、GFM の各拡張（`roadmap.md` の Future Phases を参照）。

## Optional Settings

既定の動作は「CommonMark だけ、内容全体、malloc と free、不正な UTF-8 はエラー、資源は無制限」である。設定で変えられるのは次のものに限る。構文の規則は変えられない。

- 方言（拡張の集合）
- 解析する範囲 `[start, end)`
- 確保関数
- 診断に付けるファイル名
- 不正な UTF-8 の扱い（エラーか、U+FFFD に置き換えて続けるか）
- 資源の上限（入力の大きさ、入れ子の深さ、ノードの数）
