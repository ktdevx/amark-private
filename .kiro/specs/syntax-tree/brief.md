# Brief: syntax-tree

## Problem
Markdown を扱うソフトは、原文の位置を保ったまま構文の構造を知りたい。既存の実装（cmark など）は原文を複製したノードを作るため、元の位置と行末記号が失われやすく、原文の置き換えのような用途に使いにくい。

## Current State
まだ何もない。project-foundation のアリーナと確保関数を使う前提である。

## Desired Outcome
- ブロックとインラインの構文木のデータモデルがある。CommonMark の全要素を表せ、方言が定める種類も登録した ID で表せる。
- ノードは原文の範囲（バイトのオフセット）と行番号だけを持ち、原文を複製しない。
- 種類ごとの属性を持つ。
  - 見出し：レベル、ATX か Setext か
  - リスト：箇条書きか番号付きか、記号、開始番号、タイトかルーズか
  - コードブロック：フェンスの文字と長さ、info の範囲
  - リンクと画像：インライン・完全参照・省略参照・ショートカットの別、dest と title の範囲、参照先の定義
  - そのほか CommonMark が必要とするもの
- 木の構造の不変条件を定義し、検査する関数がある（テストとデバッグに使う）。
  - 範囲は内容の中にある。
  - 子は親の内側にある。
  - 兄弟は重ならず、原文の順に並ぶ。
- 読み取り専用でたどる公開 API がある。親・最初の子・次の兄弟、種類、範囲、行、属性を返す。再帰を使わずに走査できる。
- 文書を解放する API がある。
- 公開する型がある。
  - 解析の設定：方言、範囲 `[start, end)`、確保関数、ファイル名、不正な UTF-8 の扱い、資源の上限
  - エラーの種類：入力の制約違反、設定の誤り、資源の上限の超過、メモリ不足
  - 診断：位置、重大度、メッセージ、ファイル名

## Approach
ノードは、アリーナ上の平坦な配列に置き、添字（32 ビット）で親・最初の子・次の兄弟をつなぐ。属性は、種類ごとの共用体か、別の配列への添字で持つ。公開 API は不透明なハンドルと関数で構成し、構造体のレイアウトは公開しない（ABI を安定させるため）。木を作る API は内部専用とする。

## Scope
- **In**:
  - ノードの種類の列挙と、方言の種類の ID の空間
  - 属性
  - 範囲と行
  - 不変条件とその検査
  - たどる API と文書の解放
  - 解析の設定・エラー・診断の公開型と、設定を検査する関数
  - 内部で木を作る API
- **Out**:
  - 解析の規則（block-parser、inline-parser）
  - 範囲から文字列を作ること（source-text）
  - 方言の規則を登録する API（dialect-extension）
  - 木を書き換える API（今回は読み取り専用）

## Boundary Candidates
- 公開するデータモデルとたどる API
- 内部で木を作る API と不変条件の検査
- 設定・エラー・診断の型

## Out of Boundary
- HTML などへの出力、Markdown の書き直し
- 翻訳の単位への分割など用途に固有の処理

## Upstream / Downstream
- **Upstream**: project-foundation（アリーナ、確保関数、行の索引）
- **Downstream**: block-parser、inline-parser、source-text、dialect-extension、spec-conformance、利用者

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: block-parser（設定を検査・適用する場所の分担）、dialect-extension（方言のノードの種類と属性）

## Constraints
- 再帰を使わない。走査も解放も、配列か明示的なスタックで行う。
- 状態を持たない。別々の文書は並行して使える。
- 公開 API は C99 で、MSVC からも使えること。
