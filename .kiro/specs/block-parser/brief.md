# Brief: block-parser

## Problem
CommonMark のブロック構造（コンテナと遅延継続行、リーフの開始と終了、タブの桁）を、仕様どおりに、入力の長さにほぼ比例する時間で、再帰を使わずに解析する部分が要る。しかも原文を複製せず、範囲として残さなければならない。

## Current State
syntax-tree（データモデルと内部で木を作る API）と unicode-tables（case folding）ができてから着手する。

## Desired Outcome
- 解析の入口となる公開 API がある。入力のバイト列と設定を受け取り、文書かエラーを返す。
  - 設定の検査と適用：範囲 `[start, end)`、UTF-8 の扱い（エラーか U+FFFD への置換か）、資源の上限、確保関数、ファイル名
  - 失敗したときは、確保したものをすべて解放し、部分的な木を返さない。
- 行を分割する。行末記号（LF、CR、CRLF）は入力のまま保つ。
- タブを桁で扱う（タブ幅 4）。タブの一部だけを消費した場合の残りの桁を記録する。
- コンテナ：ブロッククォートとリスト項目。遅延継続行を扱う。
- リーフ：
  - テーマの区切り
  - ATX 見出しと Setext 見出し
  - インデントされたコードブロックとフェンスのコードブロック
  - HTML ブロック（7 種類の開始条件と終了条件）
  - 段落
  - 空行
- リストのタイトとルーズの判定
- リンク参照定義：解析し、ラベルを正規化し（case folding、空白の畳み込み、999 文字の上限）、定義の表を作る。
- 行ごとのプレフィックスの情報を記録する。source-text が論理的な文字列を組み立てるために使う。
- インライン解析に渡す内容（段落や見出しの内容の範囲）を用意する。
- 方言の差し込み口の位置を、設計の段階で確保しておく（ブロックの開始と継続）。

## Approach
cmark と同じく、行ごとに開いているコンテナとの一致を確かめ、新しいブロックを開始し、内容を追加する。開いているブロックは明示的なスタックで管理する。リンク参照定義は段落を閉じるときに取り出す。定義の表は、正規化したラベルをキーとするハッシュ表で、アリーナに置く。

## Scope
- **In**:
  - 解析の入口
  - 設定の適用
  - ブロック構造
  - リンク参照定義と定義の表
  - 行ごとのプレフィックスの記録
  - 資源の上限の検査（入れ子の深さ、ノードの数、入力の大きさ）
- **Out**:
  - インライン構造（inline-parser）
  - 文字列を組み立てること（source-text）
  - 差し込み口の公開 API と、結果の検査（dialect-extension）
  - spec.txt 全体を通すことの確認（spec-conformance）。ただし、ブロックに関わる例は、この spec の単体テストで確かめる。

## Boundary Candidates
- 解析の入口と設定の適用
- 行の走査とコンテナの照合
- リーフの開始と終了
- リンク参照定義と定義の表

## Out of Boundary
- BOM の除去、フロントマター（利用者が範囲で除く）
- 規則を設定で変えること

## Upstream / Downstream
- **Upstream**: syntax-tree、unicode-tables、project-foundation
- **Downstream**: inline-parser（定義の表、内容の範囲）、source-text（プレフィックスの記録）、dialect-extension（差し込み口）

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: inline-parser、source-text、dialect-extension

## Constraints
- 再帰を使わない。時間は入力の長さにほぼ比例する。
- グローバルな状態を持たない。
- 対象は CommonMark 0.31.2。
